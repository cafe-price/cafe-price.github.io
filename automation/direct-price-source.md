# 서버에서 상품별 가격을 확인하는 경로 조사

2026-11-26 갱신. 사용자가 유료 서비스를 거절했다. Omkar 코드는 참고용 비활성이며 정기 워크플로에서 제거했다. 구독·키 발급·과금은 하지 않았다. 아래 비용과 활성화 설명은 조사 기록이며 현재 실행 지시가 아니다.

## 파트너스 API 재검증

2026-11-26 12:41 KST, 기존 GitHub Secrets로 검색 API 4회 실행: 인증/API 오류 없이 기존 판매 옵션 2개 가격을 실제 갱신했다. 코코씸 코코넛밀크(9200473378) 96,000 → 80,180원, 포담팩 컵홀더(7460888891) 25,630 → 25,800원. 525개 목록은 그대로 유지했다. 실행: https://github.com/cafe-price/cafe-price.github.io/actions/runs/45750510627

같은 날 10:49 KST 실행에서도 8회 호출로 13개를 확인했다. 피클의 기존 코드와 현재 수집기는 동일한 `products/search` API 및 서명 함수를 사용한다. 웹 상세페이지 접근 차단은 이 API의 접근 차단이 아니다. 추가 유료 수집기는 전체 커버리지의 후보였을 뿐, 현재 무료 API 수집에 필요한 조건이 아니다.

- 525개 기존 상품 URL 모두 itemId와 vendorItemId를 포함한다. 상품을 식별할 번호 자체가 없는 문제는 아니다.
- 검색에서 누락됐던 아이스컵과 단가 파싱에 실패했던 커피는 지정한 상품·옵션 URL로 현재 로컬 브라우저에서 열린다. 이 브라우저 세션의 성공은 무인 서버 성공을 뜻하지 않는다.
- 커피 URL의 일반 Python HTTP 요청은 로컬과 GitHub 호스팅 서버 모두 403을 반환했다. 서버 진단 실행: https://github.com/cafe-price/cafe-price.github.io/actions/runs/45562264224 (2026-11-25 15:39 KST). 진단 작업 자체의 success는 HTTP 결과 기록 성공이며 가격 수집 성공이 아니다. 차단을 우회하거나 로컬 로그인 쿠키를 서버로 복사하지 않았다. 서버 브라우저 방식은 아직 검증하지 않았다. 진단 워크플로는 수동 실행 전용으로 남겼다.
- 상품 페이지 URL의 itemId와 화면의 상품번호가 다를 수 있음을 컵 상품에서 확인했다. 요청 URL만 보고 선택 옵션이 일치한다고 판정해서는 안 된다.
- 판매자 Open API의 상품 조회는 판매자 권한 범위에 한정된다. 파트너스 키로 다른 판매자의 재고·가격을 모두 조회하는 대체 경로로 쓰지 않는다.
  https://developers.coupang.com/ko/api/products/querying-product
- 외부 APICK 쿠팡 상품 조회 API는 상품번호 단위로 조회한다고 문서에 명시하고 있으며 응답 표준 URL에서 쿼리스트링을 제거한다. 옵션 지정·반환 vendorItemId를 검증할 수 없어 현재 카탈로그의 정확한 판매 옵션 갱신에 연결하지 않았다. 유료 호출도 하지 않았다.
  https://apick.app/dev_guide/coupang_product

## 연결 전에 필요한 검증

PC와 로그인 세션에 의존하지 않는 서비스에서 정확한 vendorItemId의 선택된 판매가를 반환해야 한다. 품절·삭제·접근 차단·가격 파싱 실패는 성공과 구별하고, 다른 옵션의 가격을 대신 저장하지 않는다. 쿠폰/회원 조건과 원본 관측 시각도 구별해야 한다.

현재 GitHub Actions의 예약 실행은 PC 전원과 무관하게 유지된다. 검색 수집의 누락 가능성은 남아 있으며 전 상품 24시간 내 갱신을 보장하지 않는다. 승인된 직접 조회 API 또는 검증된 서버 수집 경로를 확보한 뒤 기존 검색 수집에 보완 연결해야 한다.

## 비용과 활성화

2026-11-26 공식 사이트 Pricing 화면: 무료 200회/월, Starter $16/월 5,000회, Grow $48/월 25,000회. 세금·환율·결제 시점 요금은 별도 확인한다. 525종을 31일간 하루 한 번 조회하면 16,275회로 무료/Starter 용량을 초과한다. Grow 범위 내에서 재시도 여유가 있다. 아직 결제·가입·유료 호출을 하지 않았다.

1. 사용자 비용 승인 후 해당 서비스에서 API 키를 발급한다. 쿠팡 ID/비밀번호가 아니다.
2. 저장소 Actions Secrets에 `OMKAR_API_KEY` 등록. 키를 채팅에 붙이지 않는다.
3. Actions Variables의 `CAFE_PRICE_CLOUD_ENABLED`를 `true`로 설정.
4. 기존 가격 수집 워크플로를 수동 실행하되 `cloud_max_requests=3`으로 실제 GitHub 인증 호출부터 시험한다. 옵션 ID와 일반가, 갱신 시각, 이력, 비용 카운터를 확인한다.
5. 성공하면 `cloud_max_requests=600`으로 전체 실행. 매시간 기존 예약에서도 당일 미확인 목록 전체를 처리하고 성공한 상품은 당일 재호출하지 않는다. 상품 수를 줄이지 않는다.

코드는 무료 체험 응답 형태와 모의 전송으로 검증했으며, 사용자 API 키를 쓰는 서버 인증 요청 및 전체 525종 성공률은 아직 검증하지 못했다. 체험 세 건 성공을 전체 성공 보장으로 해석하지 않는다. GitHub 예약 지연·업체 장애·품절·삭제는 발생할 수 있으며 확인 실패를 최신 가격으로 위장하지 않는다.

코드: `scripts/refresh_cloud.py`. 요청은 헤더 `API-Key`와 `product=<정확한 URL>`을 사용해 `https://coupang-scraper.omkar.cloud/products/details`로 보낸다. 하루 700회·월 24,000회·상품당 하루 2회 제한, 4시간 재시도 간격, 6시간 업체 오류 중지, 4개 동시 요청, 실행당 36분 작업 제한을 둔다. 매 4개 응답마다 기존 JSON과 이력을 저장해 중단 후 이어간다. 고객용 운영 통계는 추가하지 않는다.
