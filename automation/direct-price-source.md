# 서버에서 상품별 가격을 확인하는 경로 조사

2026-11-25 확인. 아직 서버 직접 조회 수집기를 활성화하지 않았다.

- 525개 기존 상품 URL 모두 itemId와 vendorItemId를 포함한다. 상품을 식별할 번호 자체가 없는 문제는 아니다.
- 검색에서 누락됐던 아이스컵과 단가 파싱에 실패했던 커피는 지정한 상품·옵션 URL로 현재 로컬 브라우저에서 열린다. 이 브라우저 세션의 성공은 무인 서버 성공을 뜻하지 않는다.
- 커피 URL의 일반 Python HTTP 요청은 로컬과 GitHub 호스팅 서버 모두 403을 반환했다. 서버 진단 실행: https://github.com/cafe-price/cafe-price.github.io/actions/runs/45562264224 (2026-11-25 15:39 KST). 진단 작업 자체의 success는 HTTP 결과 기록 성공이며 가격 수집 성공이 아니다. 차단을 우회하거나 로컬 로그인 쿠키를 서버로 복사하지 않았다. 서버 브라우저 방식은 아직 검증하지 않았다. 진단 워크플로는 수동 실행 전용으로 남겼다.
- 상품 페이지 URL의 itemId와 화면의 상품번호가 다를 수 있음을 컵 상품에서 확인했다. 요청 URL만 보고 선택 옵션이 일치한다고 판정해서는 안 된다.
- 판매자 Open API의 상품 조회는 판매자 권한 범위에 한정된다. 파트너스 키로 다른 판매자의 재고·가격을 모두 조회하는 대체 경로로 쓰지 않는다.
  https://developers.coupang.com/ko/api/products/querying-product
- 외부 APICK 쿠팡 상품 조회 API는 상품번호 단위로 조회한다고 문서에 명시하고 있으며 응답 표준 URL에서 쿼리스트링을 제거한다. 옵션 지정·반환 vendorItemId를 검증할 수 없어 현재 카탈로그의 정확한 판매 옵션 갱신에 연결하지 않았다. 유료 호출도 하지 않았다.
  https://apick.app/dev_guide/coupang_product

## 연결 전에 필요한 검증

PC와 로그인 세션에 의존하지 않는 서비스에서 정확한 vendorItemId의 선택된 판매가를 반환해야 한다. 품절·삭제·접근 차단·가격 파싱 실패는 성공과 구별하고, 다른 옵션의 가격을 대신 저장하지 않는다. 쿠폰/회원 조건과 원본 관측 시각도 구별해야 한다.

현재 GitHub Actions의 예약 실행은 PC 전원과 무관하게 유지된다. 검색 수집의 누락 가능성은 남아 있으며 전 상품 24시간 내 갱신을 보장하지 않는다. 승인된 직접 조회 API 또는 검증된 서버 수집 경로를 확보한 뒤 기존 검색 수집에 보완 연결해야 한다.
